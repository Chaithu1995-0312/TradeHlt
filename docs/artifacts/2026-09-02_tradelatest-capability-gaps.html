Orient — capability audit, 2026-09-02

What Tradelatest has built
and what it still can't do.

Tradelatest scores every M15 candle through four engines, plans an execution, and gates capital through one risk authority — and around that spine it has built governance, research, and meaning-tracking infrastructure well beyond a typical backtest project. This audit reads five of its own artifacts as authoritative and asks a narrower question than "is the code good": which capabilities the platform's own documentation says it needs are still missing, half-built, or disconnected — and what unlocks the moment each one lands.

§2 — Missing control planes

Nobody's steering the orchestration layers

Orphaned

UnlocksA real pause/resume/override control for a human operator once live trading exists — today that lever has no wire running to it.
EvidenceF-013 (Certain) · src/execution/loop.py:31 · zero callers confirmed

Orphaned

§8 — Synthesis

Three root gaps, not thirty-two symptoms

Most of the thirty-two gaps above are downstream of a small number of missing root capabilities. Building any one of these three would collapse several other cards at once — which is the point of naming them separately from the full list.

ROOT 01

No production live rail

Directly causes §1's "zero live P&L," §6's "no live-fill validation," and §7's entire section. The paper rail and Feature Store fix already exist — this is the single highest-leverage build.

ROOT 02

No git-tracked lineage

Underlies §3's unsafe-to-fold telemetry, §1's reproducibility gap, and the fact that every finding's evidence trail lives only on one machine. A resolver + tracking policy fixes both at once.

ROOT 03

CRT identity split-brain

Feeds §5's parity ceiling and its own multi-file-ritual cost, and is the concrete first instance of the coverage gap the whole Semantic OS exists to eventually close. A design already exists — only the implementation is missing.
