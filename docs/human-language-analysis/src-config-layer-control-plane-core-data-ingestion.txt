### 1. `market_router.py` — 72 lines

**File Purpose:**
Contains only two market profiles (FOREX vs CRYPTO) as hardcoded dicts, a classifier, and a router function that returns a populated `CRTConfig` dataclass. This is the market-type branching point: every config that enters the system goes through here first.

**Runtime Role:**

**Trust Classification: CANONICAL**
Source proof: `get_crt_config()` is the sole producer of `CRTConfig` instances. The stack guard at line 57-62 is in production.

**Failure Modes:**

### 2. `config_builder.py` — 234 lines

**File Purpose:**
Central factory for `CRTConfig`. Enforces the architecture rule that ALL config creation must go through `ConfigBuilder.build()`. No other code path may construct a `CRTConfig` directly.

**Runtime Role:**
Entry point for every component that needs a CRTConfig. Called by `production_config.py::load_prod_config_from_registry()` and by any integration code that builds a config for a specific instrument.

**Key Methods:**

**`ConfigBuilder.build(instrument, overrides=None)` → CRTConfig**
- **Invocation sources:** `production_config.load_prod_config_from_registry()`, test code, scripts
- **Downstream calls:** `get_crt_config(instrument)` → returns a frozen CRTConfig, then `dataclasses.replace(base, **overrides)` if overrides provided
- **Runtime flow:** Gets base config from router → validates override keys → applies via `replace()` → returns immutable frozen dataclass
- **Side effects:** None. Pure function.
- **Failure mode:** `ValueError` if unknown override key. No silent fallback.

**`ConfigBuilder.from_existing(instrument, existing, extra_overrides=None)` → CRTConfig**
- **Purpose:** Reconstruct a config from a previously-used CRTConfig (backtest replay pattern). Carries forward ALL fields from existing as overrides on top of fresh router base.
- **Runtime flow:** `dataclasses.asdict(existing)` → merge extra_overrides → re-root through router → apply merged
- **Downstream calls:** `get_crt_config(instrument)` → `dataclasses.replace()`
- **Failure mode:** If `existing` has fields that no longer exist in CRTConfig (schema drift), `replace()` will raise `TypeError` because `_validate_override_keys` only checks user-provided overrides, not the existing config fields. This is a corruption risk during schema migration.

**`_validate_override_keys(overrides)` → None**
- Hidden default: Uses `frozenset` of CRTConfig field names at module load time. If CRTConfig fields are added/removed between deployments, this set is stale until restart. No dynamic re-computation.

**Trust Classification: CANONICAL**
Source proof: Enforced stack guard, frozen config, key validation.

### 3. `crt_engine_v2.py` — 1727 lines

**File Purpose:**
The entire Candle Range Theory (CRT) deterministic state machine trading engine. Contains 5 modules: RangeDetector, StateMachine, UltronRiskEngine, ExecutionEngine, ResetLogic, and the CRTEngine orchestrator. This is the core trading logic.

**Runtime Role:**
Processes candles one-at-a-time through a deterministic state machine: RANGE → SWEEP → DISPLACEMENT → EXPANSION → RETEST → EXECUTION → RESOLUTION. Decisions are rule-based, no ML. Called by `BacktestRunner` (in `runtime/backtest_v2.py`) for backtesting, and by `live_engine_hook` for live trading.

**Key Classes:**

**`CRTConfig` (frozen dataclass, 3538-353)**
- **Purpose:** All CRT engine tunable parameters. Frozen after creation.
- **Ownership:** Created exclusively through ConfigBuilder.
- **Hidden defaults:** `sizing_bands` default `[(0.75, 0.010), (0.55, 0.005)]` means 1.0% risk at tier 1, 0.5% at tier 2. `allowed_sessions` default `("LONDON", "NEWYORK", "OVERLAP")`. `retest_depth_max` default 0.25.

**`Candle` (dataclass)**
- **Purpose:** Single OHLCV candle with computed properties (body_ratio, midpoint, is_bullish).
- **Runtime role:** Every engine state transition is driven by a Candle.

**`EngineState` (dataclass)**
- **Purpose:** Mutable runtime state for the CRT state machine. Holds current_state, active_range, sweep_event, risk_score, active_trade, cached_features, EMAs.
- **State mutations:** Every `process_candle()` call mutates this. `reset_to_range()` clears most fields but preserves `active_trade` (via guard in `should_reset`).
- **Corruption risk:** `cached_features` is set at RETEST_CONFIRMED time (line 725-744) but consumed at EXECUTION time (line 1641). If state resets between retest and execution (HTF change, sweep expiry), `cached_features` becomes None and `build_trade()` will crash at line 1246 with `KeyError: 'double_sweep'` or silently produce wrong intent.

**`RangeDetector`**
- **`detect_htf_range(candles, htf_candle_id, session)` → Range:** Determines HTF range from high/low extremes of a candle list. Pure function.
- **`compute_atr(candles, period=14)` → float:** Standard ATR computation from last `period` candles (default 14).
- **`detect_sweep(candle, active_range, prev_sweep, current_index)` → Optional[SweepEvent]:** Checks if candle high exceeds range high (SHORT sweep) or candle low breaches range low (LONG sweep). Also classifies geometric archetype via `crt_sweep_taxonomy.classify_sweep()` — **diagnostic only, does NOT influence scoring.**

**`StateMachine`**
- **Runtime flow (state transitions):**
  1. `try_range_to_sweep`: Detected sweep → sets direction, enters SWEEP
  2. `try_sweep_to_displacement`: Candle body_ratio > min AND wick_size > ATR_multiplier × ATR AND sweep not expired → enters DISPLACEMENT. **Expiry guard at line 576-588**: if `current_candle_index - sweep.candle_index > max_sweep_age_candles` (default 20), resets to RANGE.
  3. `try_displacement_to_expansion`: Directional close + close > displacement_close + expansion_atr_min_distance × ATR → enters EXPANSION
  4. `try_expansion_to_retest`: Price retraces to range boundary within adaptive ceiling (max of retest_depth_max × range_size, retest_atr_depth_fraction × ATR) AND [PATCH 7] disp_strength ≤ max_displacement_strength (default 2.0) → enters RETEST, computes cached_features
  5. `try_retest_to_execution`: Called after soft-confirmation manifold approves

- **`reset_to_range(state, reason, candle, ev_logger)` → None:** Clears sweep_event, displacement_candle, retest_candle, risk_score, direction, cached_features, evaluating_soft_conf flags. State mutation: sets current_state=RANGE.

**`UltronRiskEngine`**
- **`compute_score(state)` → RiskScore:** Weighted fusion of sweep_score (0.35), breakout_score (0.25), retest_score (0.20), time_score (0.20) × decay_factor (exponential based on candles since retest).
- **`approve_with_soft_conf(state, conf_candle)` → (bool, reason, S):** Replaces the original `approve()`. Computes structural score G (from `compute_score`), then confirmation score C (from `compute_soft_confirmation`), then geometric fusion S = G^α × C^β. Tier 1: S ≥ 0.75 (full risk). Tier 2: S ≥ 0.30 (half risk).
- **`compute_soft_confirmation(candle, state)` → float:** Continuous score ∈ [0.20, 1.0] from body_ratio, EMA momentum, Gaussian distance decay, displacement strength. Weak-link penalty = min(body, mom).
- **`approve(state)` → (bool, reason):** Legacy binary approve (still used? Dead code analysis needed — `approve_with_soft_conf` appears to be the active path).

**`ExecutionEngine`**
- **`build_trade(state, risk_engine)` → Optional[Trade]:** Computes SL anchored to displacement candle extreme + ATR buffer. TP1/TP2 anchored to risk distance (R-multiples). Intent-derived TP multipliers via `_derive_trade_intent(cached_features)`. Risk_pct from sizing_bands.
- **`update_trade(trade, current_price)` → str:** TP1 hits → 50% partial close + trail-SL to 0.5R (Phase-A.2). TP2 hits → close runner. SL hits → full loss or breakeven if TP1 already hit.
- **`generate_trade_id(instrument, opened_at, direction, entry)` → str:** MD5 hash of normalized fields → 16 hex chars.
- **Failures:**
  - Line 1230-1241: Inverted SL guard — rejects trades where SL is on wrong side of entry. Logs warning, returns None.
  - Line 1192-1195: Missing range or sweep → returns None with log error.
  - Line 1208-1210: No displacement candle → returns None with log error.

**`CRTEngine` (orchestrator)**
- **`process_candle(candle, htf_candle_id)` → dict:** Main entry point. Auto-assigns candle index, updates bounded ATR buffer, updates EMAs, checks reset, manages active trades, runs state machine, handles soft-confirmation manifold.

**# human execution explanation**
What ACTUALLY happens when you call `process_candle()`:
1. The engine stamps the candle with a monotonically increasing index.
2. It appends the candle to a bounded buffer (atr_period × 3 = 42 candles max).
3. It recomputes ATR from the buffer.
4. It updates EMA-2 and EMA-5 (continuous momentum smoothing).
5. It checks `ResetLogic.should_reset()` — if an active trade is in OPEN or TP1 state, reset is suppressed. If HTF changed mid-setup (EXPANSION or RETEST), reset is also suppressed. Otherwise retrace > 50% or 1.618 extension triggers reset.
6. If reset fires and there's an active OPEN trade, it's STOPPED (not TP1-protected).
7. If no active trade, it drives the state machine forward on the current candle.
8. When RETEST is confirmed, `cached_features` (retest_depth, body_ratio, disp_strength, session, double_sweep) are computed and stored with hard assertions.
9. `evaluating_soft_conf` flag is set, and up to `soft_conf_max_candles` (default 3) candles are evaluated via `approve_with_soft_conf`.
10. If approved, session filter and discount/premium zone filter are checked, then the trade is built, opened, and the action dict is returned with `TRADE_OPENED`.

**Failure Modes & Corruption Risks:**
- **BitNet dependency**: If `use_bitnet=True` but BitNet is unavailable, `bitnet_score()` will crash (import is at top of file: `from bitnet.bitnet_inference import bitnet_score`). No try/except.
- **`cached_features` assertion crash**: Lines 746-747 have hard `assert` statements. If `disp_strength` or `body_ratio` missing from cached_features dict (e.g. due to schema mismatch), the engine crashes with `AssertionError` during RETEST_CONFIRMED.
- **`validate_features` swallow**: Lines 748-761 have a try/except that silently swallows schema validation errors. Bad features proceed with a debug log.
- **EMA seed**: Line 254-255 seeds both EMAs to first close value. Until both have diverged (which takes ~5-10 candles), momentum scores are noisy.
- **Floating point**: No decimal.Decimal used. Float comparisons at line 1230-1241 (SL vs entry) can produce edge cases near zero.

**Trust Classification: LIVE** (actively used in backtest and live execution paths)

### 5. `crt_gaussian_scorer.py` — 192 lines

**File Purpose:**
Gaussian (bell-curve) proximity scoring for CRT setups. Uses empirically-calibrated means and variances from backtest observations (EURCAD M15, 200 retest observations 2024-2025). The formula is a weighted geometric mean: final = (s_retest^0.35) × (s_body^0.30) × (s_disp^0.20) × (s_time^0.15).

**Runtime Role:**
Called by the scoring pipeline (via `ScoringEngine`). Provides a second opinion alongside the CRT engine's own scoring.

**Key Methods:**

**`compute(features, candle_idx, current_index)` → dict:**
- **Inputs:** `features` dict with `retest_depth`, `body_ratio`, `disp_str`, `retest_index` keys
- **Hard filters:** retest_depth < 0.025 or > 1.0 → reject. disp_str > 3.670 → reject (95th percentile — 1.80 rejected 100% of real trades)
- **Output:** dict with `score`, `p_win`, `components`, `decision` (always "advisory"), `reject_reason`

**`extract_features(state, candle_idx)` → Optional[dict]:**
- Primary: uses `state.cached_features` (set at RETEST_CONFIRMED in crt_engine_v2.py)
- Fallback: live extraction from state fields (less reliable through confirmation window)
- Returns None if features cannot be computed (safe no-op)

**Hidden defaults:**
- `RETEST_MU = 0.237`, `RETEST_S2 = 0.040` — real EURCAD M15 mean/variance
- `BODY_MU = 0.847`, `BODY_S2 = 0.021` — real mean/variance
- `DISP_MU = 2.177`, `DISP_S2 = 1.196` — real mean/variance
- `SIGMOID_K = 4.5`, `SIGMOID_X0 = 0.50` — sigmoid calibration
- Config loaded from production JSON `gaussian_scorer` section at module init; if section missing, falls back to hardcoded defaults silently (try/except at line 14-18).

**Failure modes:**
- `_reject()` returns score=0.0, p_win=0.0, decision="reject" — downstream caller must check `reject_reason` field. If caller doesn't check, a rejection looks like a neutral score.
- Floating point at edge of _gaussian: if x is far from mu relative to sigma2, exp() underflows to 0.0, making final_score = 0, p_win → 0.5.

**Trust Classification: LIVE** (empirically calibrated, actively used)

### 7. `execution_planner.py` — 506 lines

**File Purpose:**
Execution Planner v1.2 — pure intent classifier + gate. Classifies trade intent (BREAKOUT / PULLBACK / LIQ_SWEEP / REVERSAL / UNKNOWN), computes entry price, delegates signal approval to `GateIntelligence`. Does NOT compute SL/TP/RR — that is CRT engine's sole responsibility.

**Runtime Role:**
Layer 2 in the 5-layer execution pipeline (after EngineRunner decision, before CRT levels computation).

**Key Methods:**

**`ExecutionPlannerV1_2.plan(engine_result, features, context)` → dict:**
- **Runtime flow:**
  1. Validate required feature keys (13 required fields: close, high, low, atr, body_ratio, disp_strength, sweep_detected, double_sweep, retest_depth, candles_since_retest, ema_fast, ema_slow, momentum_score)
  2. Validate price sanity (close > 0, atr > 0, high > low)
  3. Check engine decision == "execute"
  4. Derive intent (LIQ_SWEEP > PULLBACK > BREAKOUT > REVERSAL > UNKNOWN)
  5. Compute entry (LIMIT for PULLBACK/LIQ_SWEEP, MARKET for BREAKOUT/REVERSAL/UNKNOWN)
  6. Gate via `GateIntelligence.decide()` — configurable weights
  7. Compute TTL, precision, execution_id (MD5 hash)
- **Output keys:** decision, execution_id, trade_intent, direction, entry_type, entry_price, gate, validity_ttl_sec, created_at, expires_at, confidence, regime, symbol, signal, score, trace

**Intent Derivation (line 324-371):**
- LIQ_SWEEP: sweep_detected or double_sweep
- PULLBACK: retest_depth in [0.3, 0.7] AND candles_since_retest <= 5 AND momentum > 0
- BREAKOUT: body_ratio > 0.6 AND disp_strength > 1.5
- REVERSAL: EMA fast/slow crossed vs direction (counter-trend)
- UNKNOWN: no match → rejected if `reject_unknown_intent=True` (default)

**Hidden defaults:**
- TTL: BREAKOUT=180s, PULLBACK=300s, REVERSAL=120s, LIQ_SWEEP=240s, UNKNOWN=180s
- risk_percent=0.5, precision_default=8, default_account_balance=10000.0

### 9. `llm_scorer.py` — 305 lines

**File Purpose:**
LLM score-computation layer. Builds prompts for numeric scoring (outputs float in [0.0, 1.0]), routes through local llama.cpp (primary) → Groq (fallback) → fail-open 1.0.

**Runtime Role:**
Called by scoring pipeline when LLM gate is active. Provides `llm_score_safe()` with circuit-breaker (returns 1.0 neutral when circuit is open).

**Key Methods:**

**`llm_score(metrics, endpoint)` → float:**
- Runtime flow:
  1. Builds prompt from metrics (win_rate, expectancy, trades, max_drawdown, expansions/retests ratio)
  2. POST to local llama.cpp server
  3. Parse response with regex for float pattern `\b(0\.\d+|1\.0|0\.0)\b`
  4. If parse fails → try Groq fallback
  5. If all fail → return 1.0 (fail-open)
  6. Every call writes to `logs/llm_audit.jsonl`

**`llm_score_safe(metrics)` → float:** Circuit-breaker wrapper. After `_FAIL_COUNT_DISABLE` failures, sets `CIRCUIT_OPEN=True` and permanently returns 1.0.

**`cached_llm_score(metrics_key)` → float:** LRU-cached (maxsize=5000). Key is JSON string of metrics.

**Hidden defaults:**
- Fail-open returns 1.0 — this means "LLM says trade is perfect" when the endpoint is down
- `CIRCUIT_OPEN` is module-level global — once tripped, never resets until process restart
- Prompt forces a single float output, but regex matches the FIRST float in the response, not the intended score
- `_groq_score` returns (1.0, "") on failure — same fail-open value

**Trust Classification: DANGEROUS** — fail-open design means "perfect score" on all failures, which is the opposite of what a risk gate should do. This is intentional per docstring ("fail-open") but classified as dangerous because it silently approves trades when the LLM backend is down.

2. Query DB for stored range (min_ts, max_ts)

**`HistoricalFetcher.detect_gaps(pair, timeframe, start, end)` → List[gap_tuples]:**
- Detects gaps > 1.5x expected candle interval
- Logs WARNING per gap — does not raise

**Priority chain:**
1. TimescaleDB (local) — serve existing rows, fetch only missing
2. MT5 Python API — fetch if `mt5_enabled=true` and MT5 initialized
3. CSV fallback — read `{pair}_{timeframe}.csv` from `csv_fallback_dir`

**Hidden defaults (from config `data_ingestion` section):**
- `batch_size` (default from config), `connection_timeout_sec` (default from config)

### Replay/Governance Contamination Risks

1. **Live → Backtest contamination**: `cached_features` computed at RETEST time persist through state resets. If the backtest engine processes live data and then receives test data without re-initialization, stale features could cross contamination boundaries.
2. **LLM audit log contamination**: `logs/llm_audit.jsonl` stores every LLM scoring request including full input metrics and prompts. This file grows unboundedly.
3. **Feature drift threshold (1.5)**: Hardcoded fallback. If features genuinely drift beyond 1.5 and no production config override exists, the RR fusion silently reverts to Gaussian — the operator would not know the RR model is not being consulted.
4. **Config hash missing**: Only a warning, not an error. A registry file without hash can be promoted and run in production without tampering detection.
