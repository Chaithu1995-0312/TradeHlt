## 2. `opportunity_scanner.py` — Ground-truth opportunity generation (LIVE | 283 lines)

**File Purpose**
Pipeline B (Research) — generates **unbiased ground-truth** opportunity logs. For every candle past warmup, simulates BOTH long and short trades with fixed SL/TP (ATR-based). CRT is intentionally NOT consulted. This is the data source that breaks the recursive training loop.

**Runtime Role**
CLI tool (`main()`) or imported module (`scan()` function). Reads M15 OHLCV CSV, writes run-scoped opportunities JSONL to `logs/{instrument}/{run_id}/opportunities.jsonl`.

**Runtime flow of `main() → scan()`:**
```
CSV → _load_csv() → FeaturePipeline.run() → enriched_df
→ for each candle (past warmup):
    → compute SL = entry - sl_atr_mult * ATR
    → compute TP = entry + tp_atr_mult * ATR
    → forward-simulate (max_forward_candles bars) with trailing stop
    → record TP_HIT / SL_HIT / TIMEOUT
    → write JSONL: {timestamp, instrument, direction, entry, sl, tp, outcome, rr_achieved, duration_candles, mfe, mae, features: {...}}
```

**`_simulate()` function (line 53-149):**
What ACTUALLY happens:
1. Start with trail_stop = entry SL price
2. Walk forward bar by bar
3. Once price moves favorably by `trail_mult * risk_distance`: trail activates
4. Trail follows peak at distance `trail_dist` behind
5. Conservative tie-break: if bar touches both TP and trail simultaneously, trail (SL) wins
6. Returns: outcome (TP_HIT/SL_HIT/TIMEOUT), rr_achieved, duration, mfe, mae

The trailing stop design populates all 4 Gaussian classes:
- class 0 (rr < 0): trail/SL hit before activation
- class 1 (0 <= rr < 1): trail triggered after partial favorable run
- class 2 (1 <= rr < 2): trail triggered after deeper favorable run
- class 3 (rr >= 2): TP hit

**`scan()` function (line 152-238):**
- **Inputs:** csv_path, instrument, tp_atr_mult (2.0), sl_atr_mult (1.0), max_forward_candles (40), warmup_candles (30), output_dir (logs), trail_mult (0.5), run_id
- **Runtime flow:**
  1. Load CSV, run FeaturePipeline
  2. Require `atr_14_raw` column (hard crash if missing)
  3. For each candle post-warmup: compute SL/TP, simulate both long and short
  4. Write header record + data records as JSONL
- **Outputs:** `Path` to the written opportunities JSONL
- **Counts tracked:** long, short, TP_HIT, SL_HIT, TIMEOUT

**Hidden defaults:**
```python
tp_atr_mult = 2.0       # 2R reward
sl_atr_mult = 1.0       # 1R risk
max_forward_candles = 40  # max bars to simulate
warmup_candles = 30     # candles to skip for indicator warmup
trail_mult = 0.5        # 0.5R trailing stop
```

**Determinism:** NOT deterministic. Uses `time.strftime` for run_id. FeaturePipeline results depend on `CANONICAL_FEATURES` order. RNG not used.

**Failure modes:**
- Missing `atr_14_raw` → `RuntimeError` (hard crash)
- `atr_raw <= 0 or NaN` → silently skipped (continues to next candle)
- Forward bars empty → silently skipped (continues to next candle)
- `max_forward_candles` reaching end of data → `TIMEOUT` outcome with realized return

**Side effects:** Creates directory `logs/{instrument}/{run_id}/` and writes JSONL file.

**Trust:** LIVE — critical data source for unbiased training.

## 5. `train_bitnet.py` — Legacy 6-input BitNet training (LEGACY | 330 lines)

**File Purpose**
Trains the legacy 6-input BitNet model from historical CSV data. Uses pure Python + numpy — no ML library. The 6 features are: body_ratio, retest_depth, disp_strength, atr, candles_since_retest, double_sweep.

**Runtime Role**
CLI tool. Runs gradient descent with MSE loss and sigmoid output. Labels are derived from forward-simulating 40 bars after each CRT signal.

**Runtime flow of `main()`:**
```
CSV → FeaturePipeline → for each candle post-warmup:
    if retest_depth > 0.05:
        extract 6 features
        simulate: if price hits TP (close+2*ATR) in next 40 bars → label=1.0
                  if price hits SL (close-1*ATR) first → label=0.0
                  timeout → skip
→ balance classes (oversample minority to match)
→ normalize features (z-score)
→ train with Xavier init, Adam-like gradient descent
→ save model JSON + update bitnet_registry.json
```

**`build_dataset()` function (line 87-147):**
- Requires `retest_depth > 0.05` — only trains on candles with sweep+retest pattern
- Timeouts are excluded (no clear win/loss gradient)
- Labels derived from candle forward-simulation, NOT from actual trade outcomes

**Critical class balancing (line 296-310):**
Uses random oversampling with seed=42 to balance wins and losses. This means the same training data always produces the same balanced dataset.

**`_update_registry()` function (line 244-263):**
Marks ALL existing entries as inactive, then adds new entry as active. This means each training run replaces the previous active model.

**Trust:** LEGACY — superseded by Gaussian NB and TradeNet. Marked as "legacy_6input" in its own schema.
