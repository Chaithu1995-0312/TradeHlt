What each departure name means, as the function leaves it:

- RANGE. No live sweep, displacement, or retest. The next bar will run detect_sweep. This is also where a close, an expiry's following bar, a failed confirmation, and a filter rejection end.
- SWEEP. This bar, or an earlier one still inside max_sweep_age_candles, stored a sweep and displacement has not passed. The next bar will run try_sweep_to_displacement.
- DISPLACEMENT. The directional impulse was accepted. The next bar will run try_displacement_to_expansion.
- EXPANSION. The impulse extended. The next bar will try the retest, and only if that fails will it consider the TTL.
- EXPIRED. The expansion TTL fired on this bar. The function does not reset in the same call, because s was copied before the branch. The next bar arrives in EXPIRED and that bar's branch calls reset_to_range.
- RETEST. try_expansion_to_retest succeeded on an earlier bar and evaluating_soft_conf is still true. There is no elif on the name RETEST. The next bar enters the soft-confirmation block because of the flag, not because of the enum.
- EXECUTION. A trade is open. The next bar handles stop and target before it ever looks at the enum. If the trade does not close, the enum is unchanged, there is no EXECUTION branch, and the bar leaves still in EXECUTION.
- RESOLUTION is not a state a finished bar is left in. The close path writes it and then reset_to_range replaces it with RANGE before return.
- SHADOW_PENDING. A sweep matched pending displacement memory. The next bar either confirms the shadow expansion or leaks back to RANGE.

So "this bar is SWEEP" is ambiguous until the clock is named. In the summary histogram it means the bar arrived in SWEEP. In L3 it means the bar ended in SWEEP. The candle's own open, high, low, and close were the inputs to the test. They are not the state.

**Two coupled fixes:** (1) layer trace becomes per-run (file system change), (2) oracle labeler joins the `lt_` spine (contract change). Then (3) three parity contracts must be frozen before labels are comparable to trades. Below is the design — code-shaped, migration-ordered.

## 1 · The two problems as one

The shared trace file is not just a maintenance problem — it's **why the labeler is on a different ID space**. The labeler reads `build_bar_matrix.py`'s output; that script reads the shared trace. Because the shared file interleaves runs, the script can't stamp which `lt_` a given matrix row came from. So it doesn't stamp any.

**Fix the trace file → the labeler can carry the spine ID → parity becomes checkable.**

One change unblocks the other.

## 2 · Layer trace — run-specific design

### Current
```
results/layer_trace/XAUUSD_layer_trace.jsonl      # append-only, 323K+ rows, all walks
results/run_<id>_XAUUSD_.../XAUUSD_layer_trace.jsonl   # manual extract, no manifest pointer
```

### Proposed
```
results/layer_trace/runs/<lt_id>.jsonl             # one file per walk
results/layer_trace/XAUUSD_layer_trace.jsonl       # frozen legacy, read-only, no new writes
results/layer_trace/index.jsonl                    # {lt_id, start_utc, end_utc, rows, sha256}
```

**Why per-run-in-shared-dir and not inside the run folder:**
- Layer trace starts writing at L0, *before* the run folder exists (lazy-folder design)
- Placing it under `results/layer_trace/runs/` decouples from folder lifecycle
- Still discoverable: `Get-ChildItem results\layer_trace\runs\lt_*.jsonl`
- The run folder can still receive a copy (or symlink) post-walk — but that's an optional convenience, not the source of truth

### Emitter change (design, not code)

```python
class LayerTraceEmitter:
    def __init__(self, cfg, run_id, instrument):
        if cfg.get("per_run_files", True):          # new default
            self._path = ROOT / "layer_trace" / "runs" / f"{run_id}.jsonl"

        self._path.parent.mkdir(parents=True, exist_ok=True)
```

One flag, default flipped. Legacy path preserved for one release cycle, then removed.

### Concurrency
Today: two concurrent walks interleave rows in one file — no locking. Per-run files eliminate the interleave. No locking needed.

### Maintenance
- **Rotation:** delete `runs/lt_*.jsonl` older than N days (configurable, default 90)
- **Index:** `index.jsonl` append-only, one line per walk close. Greppable, small.
- **Manifest pointer:** `run_manifest.json` already exists — add `layer_trace_path: "results/layer_trace/runs/lt_..._XAUUSD.jsonl"`. The manifest becomes the single lookup from canonical → trace file. Closes the earlier "which file is this run's trace?" gap.
