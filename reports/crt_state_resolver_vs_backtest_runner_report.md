## Executive Summary

The codebase has **two parallel but complementary pathways** for converting market data (OHLCV candles) into CRT states:

| Aspect | **CRTStateResolver** | **BacktestRunner** |
|--------|----------------------|-------------------|
| **Purpose** | Standalone state inference from feature vectors (research/replay mode) | Full backtest orchestration with candle streaming + feature pipeline integration |
| **Input** | 39-dim feature vector OR feature dict | CSV file path + BacktestConfig |
| **Output** | CRT state string (one of 9) | BacktestMetrics + trade ledger |
| **Memory** | Maintains per-bar CRTStateMemory (current_state, counters) | Maintains engine state across HTF windows |
| **State Machine** | Passive resolver (reads predicates, evaluates per-bar) | Active orchestrator (engine drives state transitions) |
| **Feature Injection** | Pre-computed externally | Generated by FeaturePipeline.run() |

**Key insight:** BacktestRunner is the *integration point* that ties them together—it pulls OHLCV through FeaturePipeline, then feeds those vectors to the CRT engine, which produces the "truth" states. CRTStateResolver is a *downstream* analysis tool that reproduces state assignments from the same feature vectors for research/validation purposes.

## 2. CRTStateResolver Path (Standalone Research Mode)

### 2.1 Class Signature

```python
class CRTStateResolver:
    def __init__(self, config_path: Path | str | None = None, 
                 ontology: dict | None = None):
        """
        config_path: path to market_crt_states.yaml (predicates per state)
        ontology: loaded market_ontology.yaml (feature semantic ranges)
        """
    
    def resolve(self, features: Mapping[str, float] | Sequence[float], 
                timestamp: Optional[Any] = None, 
                force_reset: bool = False) -> str:
        """
        features: 39-dim vector OR {name: value} dict
        timestamp: for gap-detection / lifecycle reset logic
        force_reset: unconditionally return RANGE
        
        Returns: one of {RANGE, SWEEP, DISPLACEMENT, SHADOW_PENDING, 
                         EXPANSION, RETEST, EXECUTION, RESOLUTION, EXPIRED}
        """
    
    def resolve_batch(self, feature_vectors: list[...], 
                      timestamps: list[...] = None, ...) -> list[str]:
        """Resolve states for multiple vectors in sequence."""
    
    @property
    def counts(self) -> dict[str, int]:
        """Per-state bar count: {'RANGE': 35159, 'SWEEP': 6987, ...}"""
```

### 2.2 State Emission Logic

**Step 1: Normalize Features**  
Convert raw 39-float vector to `dict[name: value]`:
```python
feature_dict = {
    CANONICAL_FEATURES[i]: float_value 
    for i, float_value in enumerate(feature_vector)
}
```

**Step 2: Encode Feature States**  
Use `FeatureStateEncoder` to map raw values → declared semantic states:
```python
# From market_ontology.yaml FM-* definitions:
body_ratio=0.85 → "HIGH_BODY"
atr=0.020 → "LOW_VOLATILITY"
momentum_score=2.5 → "STRONG_MOMENTUM"
```

**Step 3: Evaluate State Predicates**  
For each state in `market_crt_states.yaml`, check the `when` block:
```yaml
SWEEP:
  when:
    body_ratio: ["HIGH_BODY", "NORMAL_BODY"]  # OR within feature
    atr: ["NORMAL_VOLATILITY", "HIGH_VOLATILITY"]
    # AND across features
```

**Step 4: First-Match Precedence**  
Return the first state whose `when` block is satisfied.  
Default: `RANGE` (always matches).

**Step 5: Memory Transitions**  
Maintain `CRTStateMemory` for multi-bar dwells:
- **SWEEP** sticky: once entered, stay ≥2 candles
- **DISPLACEMENT** memory: HTF reset may set `pending_displacement_active` (shadow)
- **EXPANSION** age tracking: TTL = max_expansion_age_candles (495 M15 = ~5.2 days)

### 5.3 Multi-Bar Dwells & Memory

**SWEEP sticky (2+ candles):**
```
Bar N: enters SWEEP (impulse detected)
Bar N+1: must stay SWEEP ≥1 more bar (min_sweep_age=2)
Bar N+2+: can transition to DISPLACEMENT or fall back to RANGE
```

**DISPLACEMENT shadow memory (cross-HTF persistence):**
```
HTF Window A: SWEEP → DISPLACEMENT → (HTF reset)
   → Sets pending_displacement_active (shadow memory)
   → TTL = 4 candles

HTF Window B (next window):
   → Shadow can re-enter SWEEP (Phase 1 logic)
   → OR decrement TTL and expire to RANGE
```

**EXPANSION age decay (Phase 3b):**
```
Bar N: enters EXPANSION
Bar N+495: if still in EXPANSION, transition to EXPIRED (TTL exceeded)
Bar N+496: EXPIRED → RANGE (one-candle soft archive)
```

## 6. Comparison: Engine-Driven vs. Feature-Predicate States

### 6.1 Semantic Parity Audit (F-069)

**The Question:**  
How well does CRTStateResolver (feature predicates) reproduce the engine's actual state sequence?

**Method:**  
Coordinate-descent sweep across 33 threshold candidates → exhaustive brute-force calibration.

**Result (XAUUSD M15, 47,197 candles):**
```
Overall parity:    88.16% (41,607 bars match)
Per-state recall:
  RANGE:           97.8% (very high confidence)
  SWEEP:           96.4%
  DISPLACEMENT:    96.2%
  EXPANSION:       10.8% (divergent construction)
  Others (<1%):    N/A

Residual mismatch (11.84%):
  Category C (divergent construction): 96.1%
    → Resolver's EXPANSION entry uses threshold gates
    → Engine's EXPANSION uses state-machine logic + sticky dwells
    → Structurally unreachable via config alone

  Category B (unreachable): 0.1%
    → States (e.g., SHADOW_PENDING edge cases) have no config equivalent

  Category D (uninvestigated): 3.8%
    → Require source-level code changes, not config tuning
```

**Conclusion:** The resolver **cannot achieve >88% parity via configuration alone**. The engine's state machine is richer than the feature predicates. This is **intentional**—the resolver is a research/validation tool, not an exact replica.

### 6.2 Where Engine Wins (State Machine Logic)

The engine maintains **live memory across bars**, whereas the resolver **re-computes per-bar**:

1. **SWEEP stickiness:** Engine remembers "swept 2 bars ago", holds in SWEEP. Resolver re-evaluates predicate, may mis-classify.
2. **HTF-window resets:** Engine has persistent `EngineState.pending_displacement_active` shadow. Resolver must inject `seed_ohlc` to replicate.
3. **EXPANSION TTL:** Engine tracks `bars_in_expansion`. Resolver has no memory across bars (state is independent).
4. **Soft confirmation scoring:** Engine accumulates confidence over multiple bars. Resolver can't capture this.

### 6.3 Where Feature Predicates Win

1. **Transparency:** CRTStateResolver is fully config-driven; every threshold is tunable.
2. **Offline replay:** Can re-analyze historical data with different thresholds.
3. **Audit trail:** Feature state (body_ratio, atr, disp_strength) is explicit.
