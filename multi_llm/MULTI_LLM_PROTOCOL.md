# MULTI_LLM_PROTOCOL.md — Handoff Mandate

> **Status:** Frozen protocol (hand-authored). **Date:** 2026-06-15.
> **What this is.** The single contract that turns four separately-operated models
> (DeepSeek · Gemini · ChatGPT · Claude) into one coherent assembly line instead of four
> independent realities. It defines *who does what*, *how a turn is structured*, and *who
> wins when they disagree*.
>
> **What this is NOT.** It is **not** a new source of truth and **not** a new doctrine. It is
> orchestration only. The truth lives in the repository (`CLAUDE.md`, `docs/current-findings.md`,
> tests, `configs/production/ACTIVE_VERSION`). This protocol grants **no new authority** — it
> never bypasses CLAUDE.md write-authority, the path-guard, the `y/N` confirm gate, or the
> `APPROVE` promotion gate. See CLAUDE.md §12 (triggers grant no authority) and §6.5 (Authority Ladder).

---

## 1. The pipeline

```
   (shared context = context/*.md, regenerated by `Compile`)
            │
DeepSeek  ──► Gemini   ──► ChatGPT      ──► Claude     ──► Tests + Findings ──► (back to Gemini)
(Planner)    (Navigator)  (Interpreter)    (Executor)      (Reality)
```

The **User is the bridge — and the principal**: you carry `context/*.md` + the next prompt between
models, choose who goes next, and give final approval. No model calls another directly (for now —
see CLAUDE.md §6.1 "no premature framework"). The User is a first-class actor, not just plumbing —
see [`roles/ROLE_USER.md`](roles/ROLE_USER.md).

Frozen responsibilities live in [`roles/`](roles/):
[User](roles/ROLE_USER.md) (Bridge / Decider) · [DeepSeek](roles/ROLE_DEEPSEEK.md) (Planner) ·
[Gemini](roles/ROLE_GEMINI.md) (Navigator) · [ChatGPT](roles/ROLE_CHATGPT.md) (Interpreter) ·
[Claude](roles/ROLE_CLAUDE.md) (Executor).

## 2. Authority hierarchy (who wins on conflict)

This **extends, does not replace**, CLAUDE.md §6.5 (Authority Ladder) and §4.0 (Runtime Truth
Precedence). No LLM owns truth.

```
Reality (live outcomes)
  > Tests + Findings (docs/current-findings.md, the pytest floor)
    > Repository (code + configs/production/ACTIVE_VERSION)
      > Shared Context (context/*.md — a derived VIEW, never authoritative on conflict)
        > User (the principal — sets the goal, approves, decides what to DO about evidence)
          > LLMs (DeepSeek / Gemini / ChatGPT / Claude)
```

The **User is above the LLMs** (directs them, approves irreversible actions and promotions) but
**below Reality/Tests/Findings** — the User decides *what to do* about evidence, never what the
evidence *is* (CLAUDE.md §6.5 binds the User too). See [`roles/ROLE_USER.md`](roles/ROLE_USER.md).

**Code & execution authority (CLAUDE.md §13, non-optional):** only **Claude** writes/edits code and
runs execution in the codebase — DeepSeek/Gemini/ChatGPT propose code only as advisory input applied
by Claude. But **advice is everyone's**: all four models (incl. Claude) contribute **recommendations**,
and **no model's advice — including Claude's — is binding** (the User weighs it; evidence settles it).
This governs *who implements*, not *what is allowed* or *whose advice counts* (User approval + all §6
gates still apply).

Corollary (from §6.5): **evidence has no authority; only demonstrated G001 improvement grants
authority.** A model's confidence score is advisory and never outranks a test or a finding.

When two authorities of similar rank disagree and the winner is unclear, the active model must
**surface a `TruthConflict`** (source A, source B, evidence, impact, recommendation) and stop —
never silently resolve it (CLAUDE.md §6.2 rule 3).

## 3. Mandatory response block (every model, every turn)

Every model ends every response with this block. It is the unit of handoff — it is what makes
context portable and drift-resistant.

```
CURRENT_TASK:        <the one story / objective in flight>
NEXT_10_STEPS:       <the visible queue — from multi_llm/build_queue.jsonl>
CONTEXT_DELTA:       <new findings / constraints / decisions / files since last turn>
FOR_NEXT_MODEL:      <target model + its role + the expected output>
PROMPT_FOR_NEXT_MODEL: <copy-paste-ready prompt for the next actor>
CONFIRMATION:        <"Was this produced by the intended role?" — DeepSeek→Gemini→ChatGPT→Claude→Gemini>
```

If `CONFIRMATION` is NO (wrong actor for this stage), stop and re-route — do not proceed.

Claude additionally obeys CLAUDE.md §6 and appends the `📝 SESSION LOG ENTRY` block to
`assistant_project.md` on every turn — the protocol does not waive that mandate.

## 4. The cycle (one story, end to end)

```
1. Compile      → regenerate context/*.md  (python scripts/context/build_context.py)
2. Pack         → bound the upload  (python scripts/context/pack_story.py --story <id>)
3. DeepSeek     → plan / decompose the next story; emit prompt for Gemini
4. Gemini       → gaps, completeness, next-10; emit prompt for ChatGPT
5. ChatGPT      → explain + EXPAND parameters up front (reduce Claude's rework); emit prompt for Claude
6. Claude       → implement surgically per CLAUDE.md §3; run Validate; append SESSION LOG
7. Reality      → tests + findings decide VALIDATED / REFUTED / INCONCLUSIVE
8. Capture      → after EACH model turn, log it verbatim
                  (python scripts/context/log_turn.py --actor <m> --story <id> --in resp.txt)
9. Update       → advance multi_llm/build_queue.jsonl + HANDOFF.md; goto 1
```

Catch up / rewind the whole thread any time (view-only):
`python scripts/context/discussion.py --full | --rewind <turn_id> | --digest`. The digest also rides
into `context/06_DISCUSSION.md` so every uploaded bundle carries "the discussion so far."

**Who does what:** steps **1, 2, 8, 9 and every approval are the User's** (the bridge/decider —
`roles/ROLE_USER.md`); the four models do steps **3–7**. The loop does not advance without the User.

**SELF-DOCUMENT routing (CLAUDE.md §6 "Two logs"):** the cycle's narrative — handoff/coordination
meta — is logged to `llm_project_assistant.md` (the workflow log). Any governed code/config change
Claude makes in step 6 is logged to `assistant_project.md` (the codebase log), as always.

## 5. Anti-drift rules

1. **Context is generated, never hand-edited.** `context/*.md` is a derived view; edit the
   *source* (CLAUDE.md, current-findings.md, the queue), then `Compile`.
2. **One queue.** `multi_llm/build_queue.jsonl` is the single story backlog. NEXT_10_STEPS is read
   from it, not invented per model.
3. **Findings are first-class.** A model that validates/overturns a conclusion must reflect it in
   `docs/current-findings.md` the same cycle (CLAUDE.md §6.2 Findings Mandate) — not just in chat.
4. **No private assumptions.** Anything a model "knows" that isn't in the repo or `context/*.md`
   does not exist for the next model. Put it in `CONTEXT_DELTA`.
5. **Reality closes the loop.** A turn is not done until tests/findings have spoken (or the step
   is explicitly measure-only).
