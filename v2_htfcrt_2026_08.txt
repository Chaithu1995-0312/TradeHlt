# Parent-Candle CRT + SMC Primitives → new active version `v2_htfcrt_2026_08`

## Context

The SujanTrader CRT transcripts (`SujanTraderCRTExp.txt`, `SujanTraderCrtExpPart2.txt`) describe a
multi-timeframe CRT framework. A read-only study (delivered in-session, this file's prior revision)
mapped it against the repo and found:

- The framework's **foundational primitive is absent**. The repo has an HTF *clock*, not an HTF
  *candle*: `HTFBuilder` (`backtest_v2.py:874-906`) counts N M15 bars and emits an opaque id with
  **zero OHLC aggregation**; `detect_htf_range` (`crt_engine_v2.py:852-867`) computes H and L but
  discards O and C; and after the first bar the reset path (`:2807-2809`) rebuilds the range from
  the **last 14 M15 bars**, not the HTF window at all.
- **No 3-candle CRT construct exists** anywhere (`grep` for parent_candle/three_candle/amd → 2
  false positives in `sl_tp_comparator.py`).
- **Bucket B is entirely absent**: no order block, FVG, breaker, mitigation, PDH/PDL, EQH/EQL, or
  CHoCH in `src/`.
- `resample.py` caps at H1/H4; MT5 fetch caps at D1; `market_reality_v1.yaml` has zero readers and
  zero tests; `tools/tv_forensic/` (Playwright) is untracked and unwired.

This plan builds all of it. **User decisions, taken with costs stated:**

| Decision | Choice | Consequence accepted |
|---|---|---|
| 3-candle wiring | **New CRT states** | `CRTState` 9→12, `VALID_TRANSITIONS` extended, CN-004 invariant rewritten, CRT closure reopen widens |
| TF ladder | **H4 + D1 + W1 + MN1** | W1/MN1 need calendar aggregation; `resample`'s associativity guarantee gets an explicit carve-out |
| Bucket B scope | **All 9 primitives** | OB, FVG, Breaker, Mitigation, PDH/PDL, EQH/EQL, CHoCH |
| Default arm | **ON immediately** | Trade ledger changes on promotion; freeze-pin re-certification + baseline recapture required |
| Feature repr | **Canonical vector slots 39→48** | `SCHEMA_HASH` + `FEATURE_ORDER_HASH` move; all 6 model families need recapture/retrain; ~11 tests unpin |

**The headline consequence of the last two:** the repo's usual safety net — "prove byte-identity"
— is deliberately given up. Verification therefore shifts from *zero ledger diff* to
**fully attributed ledger diff**: every changed trade must be explained by a named mechanism.
That is the acceptance bar throughout.

Deferred by user: 3M/6M tiers, pending deeper history (2-yr corpus → only 24 monthly candles).

## Phase 1 — Real parent candles (calendar-true)

**Critical distinction to preserve:** `HTFBuilder` windows are *count-based* and stream-offset
dependent; `resample` buckets are *calendar-floored*. These are different objects and must not be
conflated. The parent-CRT track uses calendar parents.

- **`src/research/resample.py`** — add `D1` to `_RULE_HOURS` as `24`. `_bucket_start(ts, 24)` gives
  the correct midnight floor because `(ts.hour // 24) * 24 == 0`; associativity holds (H4 ⊂ D1).
  One-line, additive to all 5 existing consumers.
- **New `src/features/calendar_periods.py`** — W1/MN1 aggregation following the
  `src/research/weekly_sweep/weekly_range.py` pattern verbatim: `isocalendar()` / `day == 1`
  grouping, inline `max(high)`/`min(low)` over the filtered subset, **lock-on-close**, and
  `None`-on-partial rather than a contaminated range. `resample`'s day-local `.replace()` floor
  cannot express these — do not try to extend it. Document the **W1 ⊄ MN1 associativity failure**
  (a week straddles a month boundary) as an explicit carve-out in the module docstring.
- **New `src/features/parent_candle.py`** — `ParentCandleBuilder(rule, keep=3)`. Emits closed
  parent `Candle`s, retains the last ≥3 (the one genuine state addition: `HTFBuilder` keeps only
  one completed window). Reuse `resample._emit`'s aggregation exactly, including `Decimal` volume
  summation for grouping-invariance.
- **`HTFBuilder`** gains `parent_candle` and `parent_history` properties. Purely additive —
  `push()`'s bool, `current_htf_id`'s format, and `seed_candles()`'s contents are untouched, so
  all 7 existing consumers stay bit-identical.

**No-lookahead invariant (non-negotiable):** never expose an in-progress parent. `_buffer` stays
private; only completed windows are readable. Test this adversarially.

## Phase 2 — The 3-candle CRT state machine

- **`src/config_layer/state_identity.py`** — add `RANGE_C1`, `MANIPULATION_C2`, `DISTRIBUTION_C3`
  to `CRTState` (9→12) and a **disjoint sub-graph** to `VALID_TRANSITIONS`:
  `RANGE_C1 → {MANIPULATION_C2, RANGE_C1}`, `MANIPULATION_C2 → {DISTRIBUTION_C3, RANGE_C1}`,
  `DISTRIBUTION_C3 → {RANGE_C1}`. Disjoint is deliberate: these are parent-timeframe states, and
  interleaving them into the M15 golden path would conflate timeframes and break every consumer.
  Mirror into the immutable view `state_topology.py:109` and the second declaration in
  `configs/formulas/market_crt_states.yaml:240` (keep both in sync — they are two records of one
  edge set).
- **New `src/config_layer/parent_crt.py`** — `ParentCRTTrack`, one instance per parent timeframe.
  Classifies `parent_history[-3:]`:
  - **C1 (range)** — the reference parent candle; its own high/low become `h_ref`/`l_ref`.
  - **C2 (manipulation)** — sweeps C1's boundary and closes back inside. Reuse
    `RangeDetector.detect_sweep`'s geometry (`crt_engine_v2.py:891-892`) against the *parent*
    range; reimplement rather than import, per the Program-8 isolation precedent.
  - **C3 (distribution)** — directional impulse away from the swept side. Reuse the **F-074
    directional displacement contract** (`crt_engine_v2.py:1105-1112`) — LONG requires a bullish
    close above the sweep, SHORT a bearish close below. Do not reintroduce unsigned energy.
- **Bridge into the M15 engine.** `process_candle(candle, htf_candle_id, parent_state=None)` — a
  defaulted keyword keeps all 6 existing call sites working. Parent state feeds the M15 track as
  a bias/objective gate. **This is the authorized behavior change** (arm ON per user decision).
- **Config** — new top-level `parent_crt` section (hash-neutral): `enabled`, `timeframes`,
  per-TF thresholds, `bias_gate_mode`. Strict `_require`-style reads with a legal-value tuple and
  no silent defaults, following `feature_pipeline.normalization_basis`
  (`feature_pipeline.py:216-248`) exactly — that is the repo's proven pattern.
- **Ontology** — seed the declared-but-empty `state_transitions:` section of
  `configs/formulas/market_ontology.yaml` with the C1→C2→C3 edges (non-frozen, invisible to
  `behavior_hash` and `fm_resolve` — the cheapest correct seam), plus 3 `structural_states` nodes.
  Also update `active_models.yaml` (currently declares 9 states).

## Verification

Byte-identity is **not** available here by design. The acceptance bar is attribution.

1. **No-lookahead (hard gate, blocks everything):** adversarial test that no in-progress parent is
   ever readable, and that the last emitted parent at bar *t* is always fully closed before *t*.
   `forward_walk`'s existing assertion style is the model.
2. **Determinism:** two identical runs → byte-identical vector and ledger.
3. **Ledger diff, fully attributed:** XAUUSD backtest before vs after. Every added/removed/changed
   trade must map to a named mechanism (parent-CRT gate, a specific SMC feature, the schema
   change). An unexplained diff is a defect, not noise.
4. **Freeze-pin regenerated + waiver-log entries filed.** New vector SHA recorded as the successor
   baseline. `pytest tests/test_feature_layer_freeze.py`.
5. **Full suite:** `python -m pytest tests/ -q`, with the ~11 dimensionality tests re-pinned to 48.
6. **VA ladder:** `PYTHONPATH=src python scripts/governance/validation_access_cli.py`. F rung
   requires every new vector feature to carry a `CLOSURE_STATUS` row, or the surface drops to
   PARTIAL. **E rung stays OPEN** (no sealed `MC-*`) — so no economic claim about any of this is
   admissible yet, regardless of how green S/I/F are. Say so explicitly in the finding.
7. `python src/runtime/baseline_capture.py --label post_htfcrt` and diff against `pre_htfcrt`.
